# GameShelf 0.1.8 — SteamGridDB 封面与平台管理

2026-11-09 已发布 **`jyh9521/gameshelf:0.1.8`** 与 **`latest`**（Linux/amd64）。

- [Docker Hub](https://hub.docker.com/r/jyh9521/gameshelf/tags?name=0.1.8)：两个远程标签摘要均为 `sha256:f01b97270fba2d239b18f5fb2418db09c88942aeef35d3d5c28cafcf25e83022`；旧 0.1.6、0.1.7 标签不变。
- 镜像源码提交：[9c1f420](https://github.com/jyh9521/Game-Shelf/commit/9c1f42073eb3740468c05c920cbc7a3149dd081c)，已推送 `main`；镜像 OCI revision 与该提交相同。随后仅补充发布记录。

## 更新内容

- 接受 SteamGridDB 两个官方图片域名，修复《时之笛》等条目选中后没有封面候选的问题。选中作品后显示选图区域；替换锁定封面须确认，保存后生效。
- 平台管理可新增、编辑名称与代号（如 `N64`）、删除未使用的平台。编辑代号保留发行、Edition 和拥有记录；仍有拥有记录引用的平台须先调整对应的发行平台。
- 从 0.1.7 升级没有新增 SQLite 迁移，备份格式仍为 v3；[资料服务变量](../METADATA.md)无需改名。

## Unraid 更新

1. 停止旧容器，保留整个 appdata 的一致性副本与容器配置。
2. 编辑现有容器，将 Repository 改为 **`jyh9521/gameshelf:0.1.8`**。保留原 `/data` 挂载、端口、PUID/PGID、代理和已配置的 API 变量。
3. 启动后检查页头为 `v0.1.8`、旧账号和游戏库正常。可用《时之笛》复测 SteamGridDB，并在平台管理修改 Nintendo 64 的代号。

回退时停止新容器，将升级前快照与原配置配套还原，再使用 `jyh9521/gameshelf:0.1.7`（`sha256:4c34d42cb052d0322a940086e45ad8552991ac409dc7ac833b115644076423d5`）。

## 复测

```sh
npm run build
npm run test:cover-platforms
docker pull jyh9521/gameshelf:0.1.7
docker pull jyh9521/gameshelf:0.1.8
npm run test:release
```

容器测试使用固定摘要的 0.1.7 和独立测试卷；SteamGridDB 用合成响应复现 CDN 地址，不使用真实 API 密钥或 Unraid 数据。

## 发布验证结果

- 发布前以 0.1.7 官方镜像创建测试库，复制到独立升级卷与回退卷。升级后原 v3 数据、会话及初始化验证码保留，没有待执行的数据库迁移。
- Docker 容器用合成 SteamGridDB 响应验证《时之笛》选图并保存；手机界面将旧 UUID 改为 N64，发行与拥有记录 ID 保留；使用中的平台删除返回 409，未使用的平台可删除。容器重建后改动保留，独立快照回退至 0.1.7 后原 v3 数据与会话恢复。
- 38 项单测、类型检查、生产构建、Compose 配置和 27 项容器 HTTP 检查通过；发布后按远程摘要拉取再通过 9 项检查。个人数据未改动，QA 容器和卷已清理。真实 Unraid 与真实 API 凭据由部署者验收。
