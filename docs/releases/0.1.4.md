# GameShelf 0.1.4 — Unraid 启动权限修复

已发布 `jyh9521/gameshelf:0.1.4` 与 `latest`，linux/amd64；远程摘要与按摘要拉取已核实：`sha256:180adfeb302b433cab64ff956943569222f9170d0df3dc63f3387b55602c8b5b`。

## 症状与原因

0.1.3 在旧 appdata 中的 setup-token 属主与 PUID 不一致、且权限为 600 时，切换到应用用户后会报 `cat: /data/setup-token: Permission denied` 并退出。旧入口只调整 /data 根目录，没有调整既有验证码文件。此前测试对齐了快照文件属主，未覆盖这种旧权限状态。

## 修复范围

- root 入口在降权前，只调整 setup-token、gameshelf.db 及其 -wal、-shm、-journal 文件到配置的 PUID/PGID，权限为 600。
- 不递归调整整个 appdata，不修改其他文件及子目录，不删除或重建验证码、数据库。
- 应用仍以非 root 用户运行；目标文件为符号链接或非普通文件时明确退出，不沿链接修改其他位置。
- 数据库迁移与 JSON 备份格式不变，保留 0.1.3 的评分筛选。

## Unraid 更新

1. 停止现有 GameShelf 容器，并备份原 appdata。不要删除原 setup-token 或数据库。
2. 编辑现有容器，将 Repository 改为 `jyh9521/gameshelf:0.1.4`，拉取并应用。
3. 保留原 /data 挂载、端口、PUID/PGID、反向代理与 Cookie 配置。模板默认 PUID=99、PGID=100；以已有设置为准。
4. 启动并用原地址访问，确认页面 v0.1.4、原账号和游戏记录仍在，新增/编辑能保存。
5. 如仍退出，提供新日志及容器的 PUID/PGID、额外参数、/data 挂载信息；不要提供 setup-token 内容。

## 回退

保留 0.1.3 镜像标签。独立副本测试验证：使用已修复属主的数据副本运行旧镜像仍能启动且记录保留；使用升级前存在错误属主的原始快照则会再次出现原错误。需要完整还原时，在停机状态使用匹配的旧镜像与 appdata 备份。
