# GameShelf 0.1.6 — 作品关系与备份 v2

2026-11-03 发布准备：目标标签 **`jyh9521/gameshelf:0.1.6`** 与 **`latest`**，平台 **linux/amd64**。远程摘要和最终验证结果在发布完成后补齐。

## 更新内容

- 原作 / 重制 / 复刻手工关联，支持库内候选搜索分页、双向跳转、编辑、解除和完整判定历史；作品、评分、拥有记录与时长分别保存。
- 按用户隔离关系与历史，校验自身、重复、反向和间接循环。
- 新增 `20261102000000_game_relations` 加法迁移；首次启动自动创建关系表，不重建旧库或凭据。
- JSON 导出升级为 v2，包含关系与历史；继续支持 v1 备份迁移、原子校验和幂等恢复。
- 保留现有评分、类型、拥有版本年份筛选，以及旧 appdata 权限修复。

## Unraid 更新

1. 更新前从页面导出 JSON，然后停止 GameShelf，保存现有 appdata 的完整一致性副本和容器配置。
2. 将 Repository 改为 **`jyh9521/gameshelf:0.1.6`**，拉取镜像并启动。
3. 保留原 `/data` 挂载、端口、PUID/PGID、代理及 Cookie 设置；原账号和数据库继续使用。
4. 确认页头 `v0.1.6`，原账号、记录与筛选正常。分别建立原作与重制作品，在详情「关联原作」中保存关系，确认双向显示与判定历史。
5. 导出 v2 备份，重建容器后确认原库、关系与历史均保留。导入演示仅在独立空实例进行。

## 回退

保留 **`jyh9521/gameshelf:0.1.5`**，旧摘要为 `sha256:1a2751416859b90d4b5c79051993fa05dae9b873c8e6159a96276ba886f195a4`。

停止新容器后，将 **升级前 appdata 一致性快照、原配置、0.1.5 镜像**配套恢复。0.1.6 已增加迁移和 v2 数据格式，单独降低镜像标签不等于数据回退。升级后的新增数据另存 v2 备份，在 0.1.6 实例中恢复；旧 0.1.5 只支持 v1，不应改写 JSON 版本号绕过验证。

## 可重复验证

```sh
npm ci
npm run db:generate
npm test
npm run typecheck
npm run build
npm run test:relations
npm run test:weekly
docker pull jyh9521/gameshelf:0.1.6
npm run test:release
```

`test:release` 使用新建并标记的 Docker QA 卷、随机回环端口和随机凭据，自动执行旧版基线、0.1.6 升级、重建、升级前独立快照回退、v1/v2 恢复及桌面/390px 检查。测试结束清理自己的容器和卷，不访问个人容器或数据。

本地工程证据位于 `engineering/release-0.1.6/`，包含原始哈希、源码快照、差异、`VERIFICATION.txt` 和可执行 `ROLLBACK.sh`。回滚脚本仅启动独立的已标记 QA 快照；重跑 `test:release` 可重建测试夹具。真实 Unraid 的更新与使用结果单独验收。
