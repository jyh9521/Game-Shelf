# GameShelf 0.1.5 — 类型与拥有版本年份筛选

发布准备：镜像 `jyh9521/gameshelf:0.1.5`，平台 `linux/amd64`。完成推送后登记远程摘要和发布验证。

## 更新内容

- 新增游戏类型 / 未分类、拥有版本发售年份 / 年份未知直接选择筛选。
- 与评分、搜索、收藏和拥有条件组合；年份、平台、商店、载体、获取方式与访问状态匹配同一发行及同一份拥有记录。
- 切换条件回到第一页，重置清除全部条件；候选来自本人完整库，编辑后刷新。
- 保留 0.1.4 旧 appdata 权限修复；数据库没有新迁移，JSON 备份仍为 `schema_version=1`。
- 页面版本直接读取 package 版本；Git 固定 shell 脚本为 LF，避免 Windows checkout 破坏 Linux 入口。
- 发布审计后将 Next.js 从 16.3.8 固定升级至 16.4.3、Zod 从 4.3.6 升至 4.6.7，并更新锁文件；重跑完整源码与容器回归。对应上游记录：[Next.js 公告](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw)、[Zod 修复](https://github.com/colinhacks/zod/pull/6652)。

## Unraid 更新与测试

1. 先从页面导出 JSON，再停止 GameShelf，保存原 appdata 的完整副本及现有容器配置。
2. 在现有容器的编辑页把 Repository 改为 **`jyh9521/gameshelf:0.1.5`**，应用并拉取新镜像。
3. 保留原 `/data` 挂载、宿主端口、PUID/PGID、反向代理与 Cookie 设置，不删除原数据库和 `setup-token`。
4. 用原地址访问，确认页头 **v0.1.5**，原账号、会话和记录仍在。
5. 验证类型＋年份＋评分组合、未知年份和重置；修改一条记录后重启容器，确认修改保留。
6. 如果暂时不用新筛选，清除类型与年份条件后应仍看到原完整库。

## 回退

保留 `jyh9521/gameshelf:0.1.4`。需要回退时停止容器，将 Repository 改回 0.1.4 并保留挂载与配置；本次没有数据库迁移。完整恢复到升级前状态时，使用停机备份的 appdata 与 0.1.4 配套恢复；升级后的新增记录另行留存。

实际 Unraid 验收由用户执行。本地 Docker 测试与实机结果分开记录。
