# 中间报告演示流程（2026-10-26 ～ 2026-11-01）

## 本周交付

源码版本 `0.1.5`，承接 0.1.4。完成需求书第 20 节的类型与发售年份筛选，沿用作品 / 发行版本 / 拥有记录的分层；本周不接入外部账号。

- 类型按已有完整字段值精确选择，不拆分 `动作 / 冒险`，不改写原值；未分类只表示字段为空。
- 年份指**本人拥有版本的发行年份**，不是作品最早发售年份。年、年月、年月日均按前四位归类；未知日期单列。
- 平台、年份、商店、载体、获取方式、访问状态必须命中同一发行及同一拥有记录。
- 候选来自本人完整库，不随当前页、搜索或其他筛选缩减；编辑后刷新，仍保留当前条件，允许显示零结果。
- 切换条件回到第一页；重置同时清除类型、年份、评分和原有条件。
- 数据库无新迁移，JSON 仍为 `schema_version=1`。

## 可重复的自动演示验证

在仓库根目录执行：

```powershell
npm ci
npm run db:generate
npm run typecheck
npm test
npm run build
npm run test:weekly
```

测试自行创建独立 SQLite 文件、随机端口、随机测试凭据及生产服务器，结束后关闭服务器。测试不连接个人实例，不读取个人初始化验证码，不修改 `.data`。Windows 默认使用已安装的 Edge；其他环境使用 Playwright Chromium，也可通过 `PLAYWRIGHT_CHANNEL` 指定已安装浏览器。

末尾 `QA_ARTIFACTS=...` 指出本次输出目录，含 `desktop.png`、`mobile.png`、`demo-backup.json`、`server.log`。`demo-backup.json` 是虚构 QA 样本，可用于独立空演示库；不含管理员、密码或会话。测试目录中的 `qa.db` 和 `setup-token` 只是临时验证环境，不作为交付备份。

## 5～8 分钟讲解路线

在独立空演示实例中，通过“备份与恢复”预览并导入生成的 `demo-backup.json`。个人实例已有数据时不执行恢复。

| 样本 | 类型 | 拥有版本日期 | 用途 |
| --- | --- | --- | --- |
| QA 星海远航 | RPG | PC / Steam：2005；PS4 / 实体：2010-03 | 5 星、已通关、收藏；PS4 是已归还借用记录 |
| QA 森林手帖 | RPG | Switch / 实体：2005-11 | 4 星；原名“森の手帖”可搜索 |
| QA 雨夜追踪 | 动作 / 冒险 | PC：2022 | 从 2020-02-29 编辑而来，旧发行不再是拥有年份 |
| QA 空白档案 | 未分类 | 未知 | 空值与未知值展示 |
| QA 同名类型 | 策略 | PC：2005-12-01 | 从完整类型值 `unknown` 编辑而来 |
| QA 待补日期 | RPG | PS4：未知 | 不猜测发售年份 |

1. **定位（30 秒）**：自托管个人游戏库，核心操作不依赖外部平台；当前为开发里程碑 1，并非整个 MVP 或外部同步 α 已完成。
2. **作品与版本（1 分钟）**：打开“QA 星海远航”，展示两份不同平台/权益的记录，解释作品级评分与拥有版本的区别。
3. **组合筛选（1 分钟）**：选 RPG，得到 3 款；再选 2005，得到 2 款；再选 PC 和 5 星，只剩星海远航。将平台改为 PS4，结果为 0，因为 2005 年的是 PC 版，不是 PS4 版。
4. **未知值与搜索（1 分钟）**：重置后选“未分类＋年份未知”，只显示空白档案。重置后搜索 `star voyage` 或 `森の手帖`，展示全角英文规范化和日文原名搜索。
5. **编辑与刷新（1 分钟）**：在独立演示库修改一个类型或发行日期，观察候选更新；当前条件不再命中时正确显示空结果，重置可重新查看。
6. **数据恢复（1～2 分钟）**：导出 JSON，在第二个独立空实例预览、恢复，核对 6 款作品、拥有记录、评分、备注和日期；已有库不会被静默覆盖。自动脚本已逐项比较恢复前后的已实现实体。
7. **手机与结尾（30 秒）**：展示 390px 页面中的直接选择按钮、未知年份和无横向溢出；说明真实 Unraid、作品关系、来源历史和外部接入的后续验收项。

## 本周验收口径

自动验证覆盖：完整类型、未分类、不同日期精度、未知年份、跨版本反例、失去拥有关系的旧发行排除、筛选候选、非法参数、分页、搜索、双账号隔离、只读查询、桌面/手机交互、编辑后刷新、备份 v1 往返与重复恢复。

学校的 11 月初中间报告和 12 月中旬 α 原型节点属于日程；需求书中的 α 指真实元数据与 Steam 接入，两者不混同。Docker/Unraid 部署模板更新至 0.1.5；发布和升级验证见 [0.1.5 发布说明](releases/0.1.5.md)，真实 NAS 验收由用户执行。
