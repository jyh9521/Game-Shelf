# Steam 账号验证与确认导入

0.1.12 起，在「Steam 预览」内提供独立的账号验证和确认导入流程。原来的任意 SteamID 只读查询仍然保留，两者不混用。

## 配置和使用

1. 配置 `STEAM_WEB_API_KEY` 和 `APP_URL`。`APP_URL` 必须是浏览器实际访问的站点根地址，例如 `https://games.example.com` 或局域网 `http://192.168.1.10:3000`，不含子路径、查询串和片段。HTTPS 部署同时设置 `SECURE_COOKIE=true`。原有实例的挂载、PUID/PGID 和其他服务变量保持不变。
2. 使用 GameShelf 管理员登录，打开「Steam 预览」，点击「通过 Steam 官方登录连接」。只在 `steamcommunity.com` 完成 Steam 登录，GameShelf 不收集 Steam 密码。
3. 返回本站后点击「完成验证」。验证绑定发起操作时的同一个 GameShelf 登录会话，10 分钟内有效且只使用一次。登录会话变化、取消或过期时重新连接。
4. 回到「Steam 预览」，点击「预览已验证账号的导入清单」。服务器只查询已验证账号，清单有效期 10 分钟；新预览会替换旧清单。无可见游戏与上游错误分别提示。
5. 每项默认「不导入」。可选择新建作品，或将一份 Steam 拥有记录关联到本人已有作品。名称候选只作参考，同名作品可看平台、标识并打开详情；找不到时搜索本人作品。缺少 Steam 标题的项目需要选择已有作品。
6. 确认所选项目后写入，最多每批 100 项。选择可跨页保留；取消确认不写库。清单失效后重新预览再选择。

## 数据边界

- 关联键为当前用户、SteamID64 和 AppID。Steam 账号、本地作品、拥有记录是不同对象，不按名称自动合并。
- 每个新关联创建一份独立的 PC / Steam 数字拥有记录，获取方式为「未确认」。这不是把原有 GOG、实体或手动 Steam 记录改成同步记录；已手动记录的 Steam 游戏可能需要自行核对重复拥有，首版不自动接管旧记录。
- 新记录采用该次查询的来源累计时长，零与未知分别保存；超出存储范围的时长保存为未知。原拥有记录的手动总时长、补记和来源时长均不修改。
- 原作品的标题、评分、备注、资料来源和手动锁定字段不变。重复导入相同账号 / AppID 跳过已有稳定关联，不覆盖时长或重新创建作品。
- 选择失效目标、外部用户作品、不在本次清单的 AppID 或冲突关联时，整批拒绝，不留下部分写入。
- 解除连接不删除已导入资料。重新验证相同账号后仍识别旧关联；更换账号不会把两个账号的拥有记录自动合并。
- 删除对应拥有记录或作品会删除其稳定关联。下一次**主动选择并确认**可以重新导入；后台同步、删除忽略规则和导入历史不是本版功能。
- 平台目录须保留名为 `PC` 的平台、商店目录须保留 `Steam`。平台代号修改不会破坏解析；名称被改走时导入会提示，不自动重建目录。

## 备份与升级

数据库只新增 Steam 账号、验证请求、预览及稳定关联四张表，不重写旧资料。JSON 导出升级为 v4，保留 v1/v2/v3 导入和幂等恢复。

v4 携带 SteamID、AppID、作品与拥有记录关联，不携带已验证账号状态、会话、验证请求、预览令牌或 API 密钥。恢复到空库后先重新验证 Steam 账号，再预览和导入；导入备份不等于证明账号归属。备份包含个人 SteamID，请按个人收藏数据保存。

回退应恢复升级前数据库与配置快照，再使用旧镜像；不要用 0.1.11 写入已经包含 v4 关联的库，也不要把 v4 JSON 交给旧版恢复。

自动化使用独立 SQLite、合成 Steam/OpenID 响应和浏览器，真实 Steam 登录、真实游戏详情可见性和 Unraid 更新由实际账号 / 设备验收另记。不会把模拟响应当作真实账号验证结果。
