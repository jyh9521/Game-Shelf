# Steam 确认导入：2026-11-24

## 目标与设计

落实 11 月 23～29 日计划：官方 OpenID 账号归属验证、按用户 / SteamID / AppID 稳定关联、人工确认导入和幂等重试。沿用 Next.js / React / Prisma / SQLite，不添加依赖。

采用独立的已验证账号导入流程，保留任意 SteamID 的只读预览。相比按名称自动合并，这样保留同名歧义；相比后台全量同步，本轮只在明确操作后写库。以上为本轮实现选择。

- 验证走固定 Steam HTTPS 端点，校验 return_to、signed、nonce、身份和服务端 check_authentication。一次性 state 绑定当前会话，有效期 10 分钟；回调同源页面通过带校验头的 POST 完成，不降低现有 Strict 会话 cookie。
- 每人暂存一个已验证账号；解除连接保留导入资料，再连接需要重新验证。APP_URL 用于固定回调来源。
- 导入预览由服务器读取已验证账号的可见库，10 分钟内有效。逐项选择新建或本人已有作品，默认不选；新建需要有效标题。已有作品的标题、评分、备注、锁定及原拥有记录不变，明确新增独立 Steam 拥有记录。
- 新 Steam 拥有记录初始化来源时长；不推断购买来源，获取方式为未知。重复导入同一 AppID 返回已有关联，不更新任何个人字段或时长。冲突、过期、缺失目标、跨用户请求整批不写库。
- 加法迁移；备份 v4 携带稳定关联，兼容 v1/v2/v3。账号认证状态、会话与临时预览不进备份，恢复后须重新验证账号才能继续导入。
- 不做后台同步、自动匹配、删除忽略规则、跨账号汇总或自动改写手动记录；下周再推进。

## 实施计划

**Goal:** 发布可确认、可回退的 Steam 导入首版。
**Architecture:** 身份协议、导入事务、备份验证和 UI 分离；全部测试使用独立数据库与合成上游。
**Tech Stack:** 现有 Next.js、React、TypeScript、Prisma、SQLite。
**Spec:** 本文设计和 docs/PROGRESS.md 上周计划。
